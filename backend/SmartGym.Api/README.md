# SmartGym API

ASP.NET Core Web API demo for SmartGym OS — Sports Center Management System.

## Run

```powershell
dotnet run --project SmartGym.Api
```

Open the URL printed by `dotnet run` to access Swagger UI.

## Local Integration Configuration

The package catalog is stored in the configured PostgreSQL database. For local
development, store credentials that are not available in this repository with
.NET User Secrets rather than adding them to `appsettings.json`.

Initialize User Secrets once, then replace each placeholder below with values
from the relevant provider:

```powershell
dotnet user-secrets set "VnPay:TmnCode" "<YOUR_VNPAY_TMN_CODE>" --project backend\SmartGym.Api
dotnet user-secrets set "VnPay:HashSecret" "<YOUR_VNPAY_HASH_SECRET>" --project backend\SmartGym.Api
dotnet user-secrets set "Smtp:Host" "<YOUR_SMTP_HOST>" --project backend\SmartGym.Api
dotnet user-secrets set "Smtp:From" "<YOUR_VERIFIED_SENDER_ADDRESS>" --project backend\SmartGym.Api
dotnet user-secrets set "Smtp:User" "<YOUR_SMTP_USERNAME>" --project backend\SmartGym.Api
dotnet user-secrets set "Smtp:Password" "<YOUR_SMTP_PASSWORD>" --project backend\SmartGym.Api
```

User Secrets are loaded in the Development environment. In PowerShell, start
the API in Development with:

```powershell
$env:ASPNETCORE_ENVIRONMENT = "Development"
dotnet run --project backend\SmartGym.Api
```

VNPay payment URLs require a merchant TmnCode and HashSecret from VNPay; SMTP
email delivery requires a working mail server and sender account. These values
cannot be generated by the application. Without them, package catalog and
pending-order management still work, but external VNPay payments and email
delivery are unavailable. Never commit real credentials.

## API Endpoints

### Authentication

```http
POST /api/auth/login
GET  /api/auth/me
POST /api/auth/logout
POST /api/auth/forgot-password
POST /api/auth/reset-password
POST /api/auth/request-email-verification
POST /api/auth/verify-email
```

### Class Booking (FR-008, BR-004, BR-005)

```http
GET    /api/classes              # Danh sách lớp học (?sport=Yoga&date=2026-09-22)
GET    /api/classes/{id}         # Chi tiết lớp học
POST   /api/bookings            # Đặt chỗ (Member, Receptionist)
DELETE /api/bookings/{id}        # Hủy đặt chỗ
GET    /api/bookings/my          # Lịch sử đặt chỗ của tôi
GET    /api/schedule/my          # Lịch cá nhân (Member/Coach)
```

### Check-in (FR-016, BR-007)

```http
POST /api/checkin                # Check-in vào cổng
GET  /api/checkin/history        # Lịch sử check-in
```

### Member Packages

```http
GET  /api/package-catalog        # Danh mục gói đang mở bán
GET  /api/package-orders/me      # Đơn và gói đã mua của hội viên
POST /api/package-orders/checkout
```

Checkout body:

```json
{
  "packageId": "sport-yoga-group",
  "durationMonths": 3,
  "paymentMethod": "qr"
}
```

Checkout creates a pending package order and invoice. The selected payment method is recorded, but no external payment is captured by this endpoint. A manager confirms receipt through `PUT /api/package-orders/{id}/confirm-payment`; this updates both the order and its invoice and activates the package period.

### Admin Package Management

```http
POST  /api/package-catalog                         # Create package
PUT   /api/package-catalog/{id}                    # Update package
PATCH /api/package-catalog/{id}/status             # Enable/disable package
GET   /api/package-orders                          # List orders
PUT   /api/package-orders/{id}/confirm-payment     # Confirm payment
```

Admin package mutations and order operations require a manager role.

## Authentication

Use Swagger UI's **Authorize** button (🔓) to set your JWT token:

1. Call `POST /api/auth/login` with email and password.
2. Copy the `accessToken` from the response.
3. Click **Authorize** → paste the token → **Authorize**.

## Business Rules Implemented

| Code | Rule | Description |
| --- | --- | --- |
| BR-004 | Chính sách đặt/hủy | Đặt: 30 phút–7 ngày trước. Hủy muộn (<2h) = trừ buổi tập. |
| BR-005 | Sức chứa & Waitlist | Tự động Waitlist khi đầy (tối đa 5 người). Đôn lên khi có người hủy. |
| BR-006 | Xung đột lịch | Chặn trùng lịch HLV và phòng tập. |
| BR-007 | Check-in vào cổng | Kiểm tra gói ACTIVE, khung giờ (Off-Peak < 16:00), còn buổi. |
